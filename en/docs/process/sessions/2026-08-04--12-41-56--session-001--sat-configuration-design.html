The filesystem is the declaration

SAT's configuration layout, reconciled against the ADR corpus. There is no manifest and no registry: every path below is resolved by reading the tree, and the mapping itself is a report you can regenerate, never a file you maintain.

One carrier, two placements

ADR-018

Every entity has exactly one assets directory, and its name is a literal transform of the entity's own name — .<name>.assets. The transform is injective and reversible, so the name is always a fact you can grep, never one you compute. Where it sits depends on what it describes.

A directory → inside test-collection/
  .test-collection.assets/

The assets directory lives within the directory it describes, so it moves with its subtree.

A file → beside guide.md
.guide.md.assets/

A file cannot contain anything, so its assets sit next to it — and its media sit inside those assets.

A generic .sat.assets beside every node was rejected: the name belongs to the entity, so .sat.assets is correct only where the entity is literally named sat. Anything matching .*.assets is metadata space, excluded from content enumeration.

Nine layers, read at read-time

ADR-025 §7, amended by ADR-032 §2

Each tier's shipped floor is read immediately before that tier's operator layer, so SAT's opinion is always the thing an operator overrides — never the thing that overrides them. Deepest stated value wins; nothing is cached.

0abin/sat/defaults/sat/metadata/dc.ymlSAT's shipped opinion
1.sat.assets/sat/dc.ymloperator's instance override
0bbin/sat/defaults/collection/metadata/dc.ymlSAT's shipped opinion
2.<name>.assets/collection/dc.ymloperator's override
0cbin/sat/defaults/archive/metadata/dc.ymlSAT's shipped opinion
3.<lang>.assets/archive/dc.ymloverride; language.yml injects the language fields
0dbin/sat/defaults/content/metadata/dc.ymlSAT's shipped opinion
4.<dir>.assets/content/dc.ymlper content directory on the path, outermost first
5.<file>.assets/content/dc.ymlthe document's own record

The stagger is by tier, not by depth. Preseeds are not a layer here: they are creation-time seeds resolved into the instance record, not something read on every resolution.

What ADR-034 decided

Proposed · v0.1.0
1

Concern parents are earned, not preemptive

A role directory gains a metadata/ parent only when a second metadata file actually lands — then dc.yml relocates into it in the same change. With resources/, that makes exactly two reserved words. The skip rule stays two words long instead of becoming a list that grows.

2

The vocabulary swap runs through the floor, not through filenames

dc.yml stays dc.yml; a future vocabulary lands as mods.yml beside it, and a shipped-floor value states which is canonical. Both records can coexist during a transition, which a renamed single file cannot do — and every filename stays greppable rather than computed.

3

The mapping is projected, never declared

sat config map renders the effective mapping on demand: every record, its role directory, its floor file, and the walk that resolves it. It is derived and disposable — regenerated, never cached, never authoritative. A projection that is never stored can never drift.

Withdrawn against the corpus

  • Five lifecycle families at the role root. This is the flat-concern-directories shape ADR-025 already rejected, with more members — five reserved words where the doctrine earns them one at a time, and a migration cost with no resolver payoff.
  • An authoritative, versioned mapping manifest. A declaration that can disagree with the filesystem is ADR-025's rejected marker file at full scale. The layout's version is the ADR corpus itself.
  • Interpolated canonical filenames. Computed names make the tree's most-read record un-greppable and break the additive transition, buying nothing the floor value does not already provide.
